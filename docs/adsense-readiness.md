# Public crawl and AdSense preparation

The production Vercel project builds with `npm run build:production`. This prepares the reviewed public sitemap, builds the existing Vite application, installs the pinned browser, saves rendered anonymous HTML, and verifies the resulting HTML and route rewrites. Production must retain its existing `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` configuration. Never supply a service-role key to this client build.

Public snapshots use the actual application and published article data. The build blocks writes, usage deductions and advertising requests. It rejects redirected pages, pages marked noindex, missing headings and common unavailable/not-found screens. Rendering failures stop deployment rather than silently publishing an empty shell. Public content changes in the database need a new deployment to refresh the initial HTML snapshot; the interactive app still reads current content normally.

`public/sitemap.xml` is the consolidated inventory. `scripts/prepare-public-seo.mjs` maintains a deliberate landing-page allowlist and discovers published database articles. Private workspaces, history and redirect aliases are excluded. Existing supplemental sitemaps use the same www origin. Adding a new landing page requires updating the allowlist. Do not derive SEO eligibility from the router's `public` flag: that flag also appears on account and admin routes.

The global AdSense script has been removed, while the publisher-account verification meta remains. No ads are enabled by this repair. Before enabling advertising, configure required consent handling and explicitly select appropriate content pages; private screens, payment pages and result-only screens must stay outside the ad inventory. The advertising privacy section includes Google and third-party cookie disclosures and links to advertising choices. Billing references now name Paystack.

Verification performed locally: TypeScript checks, Vite production build, and initial HTML/canonical/rewrite checks for 45 public URLs, including published database articles. These checks establish technical HTML availability, not Google's indexing decisions or AdSense approval.

After deployment, verify the public HTTP responses and redirects. Inspect representative pages in Search Console using Live Test and submit `https://www.aidetector.cx/sitemap.xml`. Search-query absence alone is not proof that the site has no indexed pages. Review the accuracy of published benchmarks, product claims, author details and legal/contact statements before an AdSense application. Some existing legal text contains company/address/security claims that this technical repair does not verify. An AdSense publisher ID is already present in source; verify the account status before deciding whether to apply, reapply or enable ads.
