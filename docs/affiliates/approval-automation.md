# Affiliate approval automation

Admin approval now grants 300 testing credits once per account, ensures a tracked personal link exists, and atomically records a transactional activation email. Approval remains required; this does not auto-approve applications. Reapproval cannot repeat either the grant or activation message.

A PostgreSQL trigger creates the outbox event. The existing register affiliate_approved action kicks the worker immediately; pg_net also dispatches after commit and a five-minute cron recovers missed or transient sends. The worker uses Resend with its existing server secret and configured sender. It has no OpenAI dependency.

Email snapshot includes the registered address, name, personal link, and current program terms. The exact provider payload is stored before the first send. Atomic claims, a stable provider idempotency key, three bounded attempts and a 20-hour retry window prevent automatic retries after the provider's 24-hour deduplication period. Ambiguous expired attempts require manual review; `sent` means provider acceptance, not confirmed inbox placement. Admins can inspect affiliate_onboarding_outbox (state, attempts, provider_message_id, last_error). The worker and its authorization RPC are service-only; scheduler credentials are encrypted in Vault.

Approved testing-grant accounts use credit-based summaries instead of the five-check introductory allowance, without changing their stored subscription. Testing access is capped at Pro web features, does not unlock API access, does not refill, and stops at zero. Ordinary free and paying users retain their existing billing rules. Prior approved users are not emailed or granted again merely by deploying this migration.

Production verification: rollback-only approval twice yielded one grant and one outbox row; summary returned 300 credits and zero trial allowance; Blogger reservation consumed 30 credits; exhausted grants could not fall back to free checks; API use remained blocked; duplicate queue claims were prevented. Nonadmin read/claim/approval checks also passed. Synthetic changes were rolled back; no customer activation email was sent during validation. Worker authenticated with its scheduler credential and returned HTTP 200 with an empty queue. Email content tests and worker Deno check passed. Full register Deno check was blocked by the local environment's connection to its pre-existing deno.land import; the deployed registration function accepted the source successfully.
